# Decision 004: singleton packaging, bounded drain and operational visibility

Status: implemented for milestone 6, with a shared Node.js/browser SDK. One server per prefix remains mandatory. No database, broker, WAL, distributed lease, failover or exactly-once contract is introduced.

## Selected behavior

Ship a native OTP application and a digest-pinned multi-stage non-root container. Keep loopback by default; allow explicit IPv4 wildcard binding only behind a private TLS proxy. Provide host/systemd, Caddy and prefix-scoped object IAM examples. Mounted credential files and environment values are mutually exclusive. AWS credentials remain static for a process lifetime; JWT refresh and cursor resume belong to the client SDK. No signing key enters a browser or image.

Replace OTP's immediate SIGTERM handling with a small typed event bridge. Gleam owns the drain policy: latch admission closed, serialize barriers behind earlier appends, preserve the exact original owner set, flush/confirm accepted data and publish a closed head. Retry temporary mailbox saturation without replacing owners. A dead/fenced owner or unconfirmed close cannot count as drained. Freeze close commit identity and reconcile an ambiguous head response just as for archival. Final persistence notices precede 1012 socket closure. A bounded deadline exits nonzero on failure; pending memory remains uncertain. The server does not claim durability on accepted or on object uploads alone.

Head **format v2** adds explicit open/closed status. Readers accept legacy v1 open heads. Segment/index formats and the wire protocol remain v1. Closure changes metadata only after pending is empty and all final data/index/head commits are confirmed. Recovery always advances the epoch, and still emits the existing conservative interrupted-epoch boundary after a clean close; this avoids silently changing client ordering or claiming a precise lost count. Older binaries intentionally fail closed on v2 heads. Rollbacks need a compatible reader.

Readiness must work before any stream exists and detect idle failures. A guarded single worker conditionally updates a small per-boot canary and validates readback periodically; it checks both read and write permissions without touching stream history. Fresh probe success, healthy owner/admission snapshots and free connection/pending capacity are required. Probe failure/staleness and drain make the node unready. Canary writes are not ownership fencing. One dedicated probe worker is separate from the bounded archive/replay pool, with no overlapping probes or growing queues.

Operational state uses a fixed-cardinality ETS boundary shared across registry restarts. Drain phase is monotonic; it cannot be reset by a restarted registry. Activity rows are PID-scoped and dead processes are reaped, including workers killed during blocked I/O. Counters and gauges contain no user-controlled labels or payloads. Service logs serialize safe context as JSON; arbitrary OTP/dependency crash reports are redacted rather than printing session terms. This deliberately limits raw crash diagnostics to prevent token/message leakage. Explicit safe storage causes are still logged.

## SDK contract

A dependency-free ESM client, TypeScript declarations and a browser example share protocol v1 handling. The Node target is 22+ with native WebSocket. Pending commands, subscriptions, receive bytes, item queues and transport buffering are bounded. Async iteration supplies credit after application processing; finite completion stops new ACKs after completion. Up to 64 completion receipts with at most 1024 outstanding positions total accept valid ACKs already in flight, without retaining event payloads or owner leases. Refresh and ID reuse invalidate the relevant receipts. Refresh uses a caller-supplied short-lived token provider, with cancellation. Reconnect resumes from a processed cursor and discards unconsumed overlap. It requires History even if the original view was latest-only; forbidden resume ends explicitly, never resets to latest. Opaque cursors are not parsed.

Publishes are never queued offline or retried automatically. A sent request with an ambiguous outcome raises a dedicated error with the application's reconciliation key. Acceptance and cumulative persistence remain separate events. Application checkpoints and idempotent side effects are outside the SDK; repeated replay or retries can duplicate processing. No npm publication is performed by this task.

## Alternatives and limits

Immediate process exit loses a pending tail and cannot implement a successful drain. Draining only uploaded segments incorrectly equates upload with authoritative publication. Reopening a new owner during drain could hide a lost tail; barriers retain the exact old process identities instead. Making readiness depend on the first active stream strands fresh deployments, while a GET-only canary misses write-permission loss. A probe per readiness HTTP request would create unbounded storage work. A shared per-tenant metrics label would create unbounded cardinality. Raw OTP crash formatting could expose JWTs and bodies.

Static environment/mounted AWS credentials are supported explicitly; a full maintained provider/refresh chain remains future work. TLS is provided by the reverse proxy. No cluster deployment or retention policy is enabled. The local benchmark establishes behavior at a small configured pending-record cap, not fleet-scale production sizing. Reverse-linked replay still needs measurement-driven checkpoint indexing for long histories. Real AWS conditional-write/IAM conformance remains an opt-in release gate.

## Verification

Tests cover delayed/failing/ambiguous final commits, close CAS fencing and legacy decode, deadline failure without false persistence/closure, retrying saturated barriers, idle empty-service readiness and blocked-probe staleness, admission capacity, secret-file conflicts/redaction, monotonic operational state and dead activity cleanup. SDK unit/type checks cover processing ACKs, finite completion, bounded queues/requests, unknown publish outcomes, refresh, forbidden resume and reconnect overlap. Native release smoke uses real HTTP/Mist and the SDK, tests graceful and failed SIGTERM, restarts the singleton, and measures a full 64-record pending cap. A separate container smoke verifies non-root/read-only execution and signal handling. Existing memory and S3 crash/replay smokes remain required. Details and measured limitations are in deployment.md and benchmarks.md.
